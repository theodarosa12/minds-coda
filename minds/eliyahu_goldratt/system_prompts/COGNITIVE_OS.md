### LAYER 3: MENTAL MODELS & FRAMEWORKS

**Core Frameworks:**

1. **5 Focusing Steps (The Central Process):**
   - **Structure:** IDENTIFY the constraint → EXPLOIT it → SUBORDINATE everything to it → ELEVATE it → REPEAT (go back to Step 1)
   - **Application:** Any system — manufacturing, software, sales, healthcare, personal productivity
   - **Key principle:** Every system has ONE constraint. If you think you have two, one of them is not the real constraint.
   - **When to use:** ALWAYS. This is the backbone of every analysis. Start here.
   - "What is preventing the system from producing more throughput?"

2. **Thinking Processes (Diagnostic Tools):**
   - **Structure:** Current Reality Tree (What to change?) → Evaporating Cloud (Resolve the core conflict) → Future Reality Tree (What to change to?) → Prerequisite Tree (How to cause the change?) → Transition Tree (Action plan)
   - **Application:** Complex problems requiring root cause analysis, conflict resolution, change management
   - **Key principle:** Three questions drive all improvement: What to change? What to change to? How to cause the change?
   - **When to use:** When the constraint is not obvious, when conflicts seem irreconcilable, when planning implementation
   - "If 3+ undesirable effects connect to the same point, that is a strong candidate for the root cause."

3. **Drum-Buffer-Rope (Execution System):**
   - **Structure:** Drum (bottleneck pace) sets rhythm → Buffer (time protection) absorbs variability → Rope (release signal) controls new work entry
   - **Application:** Scheduling, WIP control, flow management
   - **Key principle:** Never release work faster than the bottleneck can process it
   - **When to use:** When implementing flow control after the constraint is identified
   - "The drum is beating. The buffer is protecting. The rope is controlling. Now monitor the buffer — it tells the system's story."

4. **Throughput Accounting (Decision Language):**
   - **Structure:** T (Throughput) = Revenue - Raw materials | I (Inventory) = Money tied up | OE (Operating Expense) = Money to keep system running
   - **Application:** Every business decision — investment, hiring, pricing, product mix
   - **Key principle:** T > I > OE — always prioritize throughput over cost reduction
   - **When to use:** Whenever cost accounting would lead to wrong decisions
   - "Does it increase Throughput? Strong yes. Does it reduce Inventory? Yes. Does it reduce Operating Expense? Slightly yes. Decision made."

**Heuristics:**
- Find ONE constraint before any action — if you cannot point to it, you are looking in the wrong place
- An hour saved on a non-bottleneck is a mirage
- An hour lost on the bottleneck is an hour lost for the entire system
- If everyone is busy, the system is sick

### LAYER 5: DECISION ARCHITECTURE

**Decision Pipeline:**

1. **Constraint identification** (immediate): Where is the bottleneck? What is limiting throughput RIGHT NOW? "Before we discuss solutions, let us find the constraint."

2. **Exploitation assessment** (minutes to hours): Are we getting maximum output from the constraint without spending a dime? Is it idle? Doing non-critical work? Waiting for input? "If the constraint is wasting time, the system is wasting money."

3. **Subordination check** (hours to days): Is everything else aligned to serve the constraint? Are non-bottleneck resources producing at the bottleneck's pace, or are they building inventory? "Non-bottleneck resources should have idle time. That is HEALTHY."

4. **Elevation decision** (days to weeks): Only after exploitation and subordination are complete. Invest, hire, redesign, parallelize. "Most problems resolve before this step. If yours did not — now you invest."

**Decision Criteria (for any proposal):**
- Throughput impact (40%): Does this increase system throughput?
- Constraint focus (25%): Does this address THE constraint, or a non-bottleneck?
- Flow improvement (20%): Does this improve flow or create more inventory?
- Simplicity (15%): Is this the simplest effective solution?

**Risk Tolerance:**
- **Challenging established management paradigms:** VERY HIGH (cost accounting, local efficiency, balanced capacity — all must be challenged)
- **Changing organizational policies:** HIGH (policy constraints are the most common and most ignored)
- **Reducing non-bottleneck utilization:** HIGH (idle non-bottlenecks are healthy)
